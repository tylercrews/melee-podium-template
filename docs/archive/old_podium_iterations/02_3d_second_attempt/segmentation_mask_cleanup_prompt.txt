Core requirements
=================

- Use a deterministic, non-generative process.
- Never modify the original mask or reference artwork.
- Preserve the original dimensions.
- Preserve intentional curves, rounded ends, diagonals, perspective edges, notches, disconnected panels, and white highlights.
- Do not use global erosion, dilation, polygon reconstruction, repeated mode filters, or repeated median filters.
- Do not let the renderer destructively clean an already-cleaned mask.

Semantic classes
================

Use these semantic classes unless the source clearly establishes another class:

- Transparent: (0, 0, 0, 0)
- Black:       (0, 0, 0, 255)
- White:       (255, 255, 255, 255)
- Red:         (255, 0, 0, 255)
- Blue:        (0, 0, 255, 255)
- Cyan:        (0, 255, 255, 255)

Maintain an exact semantic label map internally throughout cleanup.

Visual antialiasing should happen after the semantic geometry is correct. Prefer applying it in the renderer. If the cleaned mask itself must be antialiased, apply deterministic boundary-only smoothing after classification while keeping uniform interiors exact.

Phase 1: Inspect the real renderer first
========================================

Before editing the mask:

1. Find the target in PODIUM_SIZES in test/colorize_podium_test.py.
2. Confirm which mask filename is actually loaded.
3. Run the current target through colorize_podium().
4. Inspect the full result and enlarged edge crops.
5. Determine:
   - whether the original or cleaned mask is being loaded;
   - which color represents the inset panel;
   - which color represents recessed or structural geometry;
   - whether mode filtering or boundary straightening changes the mask;
   - whether the renderer antialiases long lines or only corners.

Keep diagnostic outputs temporary and delete them afterward.

Phase 2: Semantic classification
================================

1. Use approximately alpha 128 to establish the semantic silhouette.
2. Identify high-confidence interior pixels for every class.
3. Preserve every high-confidence seed throughout cleanup.
4. Resolve ambiguous pixels using:
   - hue and saturation;
   - neighboring-class continuity;
   - connected components;
   - local boundary direction;
   - whether the component contains a high-confidence seed.

Do not use nearest RGB alone.

Black/red transitions require special handling:

- Dark, strongly red-dominant pixels continuing a red region belong to red.
- Neutral dark pixels belonging to an established outline remain black.
- Do not allow connected dark transition pixels to create black teeth inside red.
- Never remove high-confidence black cores.

White handling:

- Preserve every white component connected to a bright-white seed.
- Keep small highlights.
- Reject gray or white-looking complementary-color blends that have no white seed.
- Do not remove white based solely on component size.

Primary colors:

- Every accepted red, blue, or cyan component should contain a high-confidence seed.
- Remove only isolated unseeded transition flecks.
- Treat legitimate disconnected panels independently.

Phase 3: Initial conservative cleanup
=====================================

Only repair unambiguous defects:

- Fully enclosed one-pixel holes.
- One-pixel class islands.
- One-pixel spikes with strong surrounding-class consensus.

Use one synchronous correction pass at most. Do not allow corrections to cascade.

Phase 4: Straight-line integrity pass
=====================================

This phase is required. Inspect every long line rather than assuming classification produced solid boundaries.

For each ordered class transition, such as red→black, black→blue, blue→black, red→cyan, and cyan→red:

1. Record the transition coordinate for every column along horizontal boundaries.
2. Produce a row-frequency table for each transition.
3. Group nearby transition rows belonging to the same physical line.
4. Identify long, demonstrably straight runs.
5. Inspect ±1-pixel deviations from the dominant row.
6. Correct only deviations inside the guarded straight span.

A run may be corrected when:

- it is at least approximately 120 pixels long;
- all transition coordinates differ by no more than one pixel;
- approximately 68–70% or more agree on one target row;
- the corrected span excludes rounded ends, diagonals, and corners;
- the surrounding class order confirms the intended boundary.

Use a corner guard of approximately eight pixels at each end of an automatically detected run.

Do not straighten:

- transparent-facing exterior contours unless specifically confirmed;
- rounded end caps;
- curves;
- diagonals;
- perspective slopes;
- notch transitions;
- areas where the dominant-row agreement test fails.

If a known straight line narrowly fails the automatic confidence test because corner samples are included:

1. Verify it visually and from its class-transition sequence.
2. Define a guarded span that excludes both ends.
3. Lock only that span to the established target row.
4. Report the number of pixels changed.

For example, if a red→black boundary alternates between rows N and N+1 across an otherwise straight rail, select the dominant intended row and replace only the one-pixel excursions. Do not rebuild the entire rail.

Phase 5: Front-face segment inspection
======================================

Inspect the front face as separate structural pieces:

1. Left outer corner.
2. Left slot and its rounded cap.
3. Left slot’s long horizontal lines.
4. Left notch diagonal.
5. Center notch and center face.
6. Right notch diagonal.
7. Right slot’s long horizontal lines.
8. Right slot and rounded cap.
9. Right outer corner.
10. Bottom silhouette.

Use enlarged nearest-neighbor crops temporarily for inspection.

For each straight front-face segment:

1. List the vertical class sequence for every column.
2. Determine the intended layer order.

Typical examples may include:

- red above;
- one- or two-pixel black outline;
- blue interior;
- another black outline;
- red trim.

3. Confirm that each straight segment maintains the same boundary rows.
4. Correct isolated pixels that break this sequence.

Examples of valid targeted repairs:

- A six-pixel black bump rising into an otherwise straight red slot edge.
- Intermittent black pixels dropping one row into a blue center face.
- A straight black rail alternating between one and two pixels thick.
- Small holes inside a long horizontal outline.

For a known straight center rail, it is acceptable to enforce an explicit row sequence over its guarded span, such as:

- row N−1: red;
- rows N and N+1: black;
- row N+2: blue.

Only do this after confirming that the entire guarded span is genuinely straight.

Do not extend the explicit sequence into:

- rounded slot caps;
- notch diagonals;
- sloped joins;
- outer corners.

When a marked defect lies on a rounded end or diagonal, compare it with neighboring transition coordinates before changing it. Preserve the point if it follows the intended curve or slope.

Phase 6: Boundary antialiasing
==============================

After semantic geometry is correct:

1. Build the rendered image from the cleaned class map.
2. Detect both horizontal and vertical semantic transitions.
3. Use the union of those edge maps, not their intersection.
4. Apply a small premultiplied-alpha blur only within the boundary band.
5. Keep uniform interiors sharp.
6. Preserve every accepted white highlight.
7. Do not move the center of any boundary.
8. Do not create fully opaque pixels outside the alpha-128 silhouette.

The purpose of this step is visual smoothing, not geometry repair. All teeth, holes, and inconsistent line thicknesses must be corrected before antialiasing.

Phase 7: Renderer integration
=============================

Update test/colorize_podium_test.py so the renderer loads the cleaned mask.

Prefer:

precleaned = mask_filename.endswith("_cleaned.png")

When precleaned=True:

- Use alpha > 127 for semantic classification.
- Quantize semantic classes once.
- Bypass:
  - smooth_classification_noise();
  - repeated 5×5 mode filtering;
  - horizontal boundary straightening;
  - vertical boundary straightening;
  - preserved-color speckle removal;
  - size-specific reconstruction intended for unclean masks.
- Use all-boundary antialiasing for the rendered output.

Confirm the correct class mapping for the target:

- Cyan may be the inset-panel class.
- Blue may be the recessed/structural class.
- Red may be the exterior/accent class.
- Black remains deliberate outline detail.
- White remains lighting detail.

Do not assume every podium size uses identical mappings.

Phase 8: Final validation
=========================

Run the real rendering path and inspect:

- the complete podium;
- top and bottom long lines;
- every black/red boundary;
- inset-panel borders;
- left and right outer corners;
- all diagonals and curves;
- every front-face rail;
- left and right slot caps;
- center notch;
- left and right notch diagonals;
- bottom silhouette;
- all white highlights.

Check for:

- black teeth inside red;
- black drops into blue;
- red swallowing black outlines;
- inconsistent line thickness;
- broken outlines;
- white dots caused by complementary-color blends;
- missing highlights;
- doubled edges;
- opaque exterior fringes;
- flattened curves or diagonals;
- damaged notches;
- pixelation along long straight lines.

Programmatically verify:

- source and output dimensions match;
- the original mask remains unchanged;
- all high-confidence semantic seeds remain;
- all accepted white-highlight pixels remain visible;
- no fully opaque rendered pixel exists outside the alpha-128 mask core;
- semantic labels are unchanged by renderer preprocessing when precleaned=True;
- every corrected straight span has zero off-row transition pixels.

Report separately:

- semantic classification changes;
- straight-line corrections;
- front-face corrections;
- any uncertain areas deliberately left unchanged.
